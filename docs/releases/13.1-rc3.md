# FCMFix ColorOS 13.1-rc3

测试版。包名与签名不变，versionCode 82，可从 13.0、13.1-rc1 或 13.1-rc2 直接覆盖安装，安装后请重启手机。

LSPosed 作用域请**同时勾选“系统框架”和“电池（`com.oplus.battery`）”**。

## ColorOS 16：可疑组件拦截与弱信号白名单显示“不适用”

在一加 13（`PJZ110_16.0.3.502`）上，系统框架有 3 项 Hook 显示失配（[#5](https://github.com/ByteJuno/fcmfix-coloros/issues/5)）。
对照该固件的 `oplus-services.jar` 后确认这些限制在这一版固件中并不存在：

- **可疑组件拦截广播 / 服务**：没有 `MaliciousRestrictPolicy`，可疑组件名单只在 `OplusAppStartupManager` 中用于拦截 Activity 启动，
  不拦截广播和服务，不影响 FCM 送达；
- **弱信号白名单**：没有 `OplusHansConnectivityManager`，Hans 中也没有弱信号场景。

现在只有识别出上述结构时才显示“不适用”；结构不同（例如多出其他可疑组件检查、方法签名改变、相关类整个缺失）时仍显示失配，
不会把真正没挂上的 Hook 当成正常。

## 包含的 13.1-rc2 改动

FCM 连接识别“假连接”（连接还在但没有收发，时间线记“FCM 无响应”）、认出走 443 端口的 FCM 连接、标出连接所在网络；
导出报告新增“GMS 的 FCM 连接”一节，修正终端中运行时 `pm` / `settings` / `am` 报“Failed transaction”。
详见 [13.1-rc2](https://github.com/ByteJuno/fcmfix-coloros/releases/tag/v13.1-rc2)。

## 测试重点

1. ColorOS 16（尤其一加 13 `PJZ110_16.0.3.502`）：自查中系统框架没有失配，可疑组件拦截广播、服务和弱信号白名单 3 项显示“不适用”；
2. ColorOS 17：自查结果与 13.1-rc2 一致，这 3 项照常生效；
3. 推送收发与 13.1-rc2 一致。
