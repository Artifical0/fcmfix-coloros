# FCMFix ColorOS 13.0-rc5

测试版。包名与签名不变，versionCode 76，可直接覆盖安装，安装后请重启手机。

LSPosed 作用域请**同时勾选“系统框架”和“电池（`com.oplus.battery`）”**。

## 新的版本号

从这一版起使用独立的版本号：`13.0-rc5`，正式版为 `13.0`，GitHub tag 为 `v13.0-rc5`。此前的版本号形如 `53-coloros-12.1`，
其中 53 是上游 fcmfix 的版本。模块仍基于上游 fcmfix 53，旧版本的 tag 和下载不受影响。

## 新功能：自动放行包含 FCM 的应用

应用列表顶部新增开关，默认关闭。开启后：

- 所有包含 FCM 接收组件的应用都会被放行，之后新安装的应用也会自动放行，不用再回来勾选；
- 在列表中取消勾选某个应用，它就会被排除，不再被自动放行；
- 手动勾选的应用（包括不含 FCM 组件的）照常放行；关闭开关后恢复为只放行手动勾选的应用；
- 开启时菜单中的“全选包含 FCM 的应用”会隐藏；筛选项“已允许”改名为“已放行”。

## 新功能：自查与导出报告

菜单新增“自查与导出报告”，点击 Hook 状态后的对话框中也有入口。不需要 Root 的部分：

- 模块是否激活、作用域、系统框架和电池的 Hook 是否生效；
- 系统框架读到的配置是否与界面一致；
- GMS 的 ColorOS 联网策略、待机分组、Doze 白名单；
- 每个放行应用的通知开关、被关闭的通知类别、待机分组、进程状态，以及**开机以来最近一次收到推送的时间和次数**。
  收到了推送却没有通知，问题通常在应用这一侧；点击应用可打开它的系统设置。

结果可一键复制，用于反馈。有 Root 时，“导出完整报告”会运行内置的 `collect-report.sh`，可选附带某个应用的通知状态和相关系统日志，
生成后分享或保存。APK 仍不申请联网权限。

## 其他

- `collect-report.sh` 可附带一个或多个应用包名，输出该应用的通知设置、进程状态和相关系统日志；
- 文档：更正开发说明中关于 53-coloros-11 深度睡眠 Hook 失效原因的错误描述（真实原因是电池作用域的 Hook 从未加载，已在 rc3 修复）。

## 包含的 53-coloros-13-rc4 改动

- 重启后的第一分钟不再漏推送；新图标；应用列表后台加载；点击模块状态申请缺少的作用域。
- 电池作用域中的 Hook 真正生效（rc3）。

## 测试重点

1. 自查页：各项显示正常；ColorOS 16 上如有“无法查询”或“未知”，请截图反馈；
2. 给一个放行的应用发消息后重新打开自查，该应用显示刚刚收到推送；
3. 开启自动放行：包含 FCM 的应用全部变为勾选；取消勾选一个后杀掉它，给它发消息，不应再被唤醒；新安装一个带 FCM 的应用，无需勾选即可收到推送；
4. 有 Root 时导出完整报告，选择一个应用，分享和保存都能正常完成；
5. 推送收发与 rc4 一致，尤其是熄屏过夜后。
