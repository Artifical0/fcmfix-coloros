# FCMFix ColorOS 13.1-rc2

测试版。包名与签名不变，versionCode 81，可从 13.0 或 13.1-rc1 直接覆盖安装，安装后请重启手机。

LSPosed 作用域请**同时勾选“系统框架”和“电池（`com.oplus.battery`）”**。

这一版让自查的“FCM 连接”更可信：以前只要内核里有一条到 5228 端口的连接就算“已连接”，
实际上 GMS 可能一直卡在“Connecting”（[#6](https://github.com/Artifical0/fcmfix-coloros/issues/6)），
也可能改走 443 端口却被当成断线（[#5](https://github.com/Artifical0/fcmfix-coloros/issues/5)）。

## FCM 连接：识别“假连接”

系统框架现在同时读取连接的收发情况。发出的数据连续重传 3 次以上没有回应，或者累计 30 分钟（不计休眠时间）
没有收到任何数据（FCM 心跳最长约 28 分钟一次），自查显示“TCP 连接还在，但……”，时间线记一条红色的“FCM 无响应”，
恢复收发后记“FCM 恢复连接（无响应约 X）”。

常见原因是本机代理（Clash / Surfing 等的 TUN）：切换网络的那几秒里 GMS 的连接进了 TUN，随后代理停止或上游断开，
本机这一端却没有被关闭，GMS 就一直守着这条不通的连接。遇到时开关一次 Wi‑Fi 或飞行模式即可恢复；
根治需要让 GMS 绕过 TUN，或在代理中开启出站 TCP keepalive。

## FCM 连接：443 端口

5228–5230 端口被封时 GMS 会改连 `mtalk.google.com` 的 443 端口。现在这种连接也显示为已连接。
GMS 平时还有很多 443 连接，因此只认远端是开机以来在 5228–5230 上见过的地址，或 `mtalk.google.com` 当前解析结果的连接。

## FCM 连接：标出所在网络

连接后面注明所在网络，例如“已连接 1.2.3.4:5228（Wi‑Fi）”；不在当前默认网络上时注明“不是当前默认网络”。

## 导出报告

- 新增“GMS 的 FCM 连接”一节：GMS 到 5228–5230 / 443 的每条连接的未确认数据、重传、多久没收发（`ss`），
  默认网络与各网络的 netId（可与 FCM Diagnostics 的 `GcmNetwork{…}` 对照），GMS 的后台联网限制，本机 TUN 接口，
  以及 GMS 自己的连接日志；
- 修正：在终端中用 `su -c sh collect-report.sh` 并写入 `/sdcard` 时，`pm` / `settings` / `am` 全部报
  “Failed transaction”，报告里 GMS 显示“未安装”。

## 包含的 13.1-rc1 改动

ColorOS 16 适配（深度睡眠白名单、深度睡眠恢复后强制停止 GMS、弱信号白名单显示“不适用”），
自动放行的应用关闭通知不再算作问题。

## 测试重点

1. 自查中“FCM 连接”正常时显示已连接和所在网络，与 FCM Diagnostics 一致；
2. 开着本机代理来回切换 Wi‑Fi / 移动数据后，如果 FCM Diagnostics 卡在“Connecting”，自查在累计约 30 分钟后显示“无响应”；
3. 5228 被封、GMS 走 443 的网络下，自查显示已连接 `…:443`；
4. 有 Root 时导出完整报告，“GMS 的 FCM 连接”一节有 GMS uid、连接明细和网络列表，联网策略不再显示“未安装”；
5. 推送收发与 13.1-rc1 一致，没有异常耗电。
